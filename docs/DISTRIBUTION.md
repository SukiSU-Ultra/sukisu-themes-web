# 两台家宽服务器组成自建 CDN

本项目提供两种运行方式：`site` 是完整网站节点（两边访问和管理、单个可切换写入节点、私有数据库副本）；`edge` 只保存资源缓存和上传分片。需要 B 也提供网站和管理入口时使用下面的 `site` 方案。两种方式都无需购买 CDN；旧 `mirrors.json` 仍可单独使用。

## 完整站点：单个可切换写入节点

每台服务器运行 `sukisu-theme-web site <本机配置.json>`。网页、登录和管理入口均可从任一站点访问；业务请求由当前写入节点处理，跟随节点运行自己的资源缓存与私有分片入口，并保存数据库和主题副本。在跟随节点注册、验证邮箱、找回密码或设备登录时，浏览器和邮件链接都停留在该节点的公开地址，写入仍由当前写入节点完成并落库，因此不会把用户转到别的站点，也不存在第二份账号数据。交接完成后同步方向随新写入节点改变。只有一个节点打开业务数据库，不做数据库双写或 SQL 冲突合并。

- 支持 2–16 个预先配置的站点。站点列表是配置地址，不代表实时可达性；管理后台显示探测结果。
- 已发布资源默认每 5 秒拉取清单并校验。完整私有副本默认每 60 秒生成/拉取，间隔可在各站点后台调整为 10–3600 秒；传输时间另计。
- 副本包含五个数据库、完整本地资源树（包括待审、上传暂存、元数据）及账号/管理配置。数据库使用 SQLite backup API；传输按 1 MiB 内容摘要分块，只传缺少的块，落盘校验长度、SHA-256 和数据库 `quick_check`。
- **周期副本不是跨五个数据库的同一事务恢复点。**只有旧业务进程排空并退出之后产生的最终副本可激活；在线周期副本不会直接开放写入。
- 目前要求本地主存储且没有任何额外存储源。S3、NAS/OpenList 来源会被拒绝，避免遗漏资源；完整站点模式也禁止在线更改存储布局和网络绑定。
- 完整站点包含私密数据，所有节点属于同一信任域。集群内部密钥可读取私有副本并参与交接，必须只保存在各服务器受保护配置内，绝不能放入 APK、网页、公开缓存或日志。

### 初次启用

1. 更新主站二进制和静态资源，在后台「分布式分发 → 完整站点与写入切换」填写各节点名称、HTTPS 根地址和私有绝对数据目录。第一行是现有主站；目录必须专用，并与原资源目录和数据库目录分离。
2. 「生成配置」返回每个站点的配置对象，包含内部密钥。将每个 `config` 对象分别保存为对应机器的 `/etc/sukisu-theme-site/site.json`，限制目录为 `0700`、文件为 `0600`。不要把外层 `configs` 数组直接作为运行配置。此动作不会部署或停止现有服务。
3. 先在维护窗口停止原普通服务，确认没有其他进程继续写原数据库；保留原数据与配置备份。A 配置的 `seed` 指向原数据，B 没有 seed。不要让旧普通服务与 `site` 同时运行。
4. 在两机启动匹配架构的二进制：`/opt/sukisu-theme-web/sukisu-theme-web-rs site /etc/sukisu-theme-site/site.json`。可参考 [systemd 模板](../scripts/sukisu-theme-site.service)。模板中的读写目录需按现有 seed 路径调整；启动用户需有原数据库、资源和配置的读写权限。
5. 两机的 Lucky/TLS 分别转发到 JSON 的 `bind`（默认各自 `127.0.0.1:8080`）。只公开监督进程的固定入口，不公开自动分配的内部业务/edge 端口。所有节点间地址需要互相可达；生产只允许 HTTPS，loopback HTTP 仅用于本机测试。TLS 代理应正确覆盖 `X-Forwarded-Proto` 和客户端地址头。
6. 在 A 点击同步，生成新副本，再在 B 点击同步拉取；核对副本时间、错误与磁盘容量。分别从两边登录、访问用户中心和管理页，并实际上传/下载验证。

每台机器的 `site.json` 是持久状态，交接会更新角色、写入节点和代次；**运行后不能用初次生成的 JSON 覆盖当前配置**。备份必须覆盖本机 JSON、私有 `dataDir`，以及首次主站仍使用的 seed 数据/配置。静态资源仍由每台节点自己的 `THEME_STATIC_DIR` 提供，需要两边一起升级。

### 维护与切换

1. 在**当前写入节点**后台选择目标节点并确认交接。全部配置成员都需在线并已跟随当前代次；任何成员落后时先恢复同步，不跳代强行切换。
2. 当前节点停止接受新业务，等待已有响应、上传/发布任务和后台写入结束，刷新统计，并等待业务进程退出。
3. 旧节点持久记录停止写入状态，生成最终副本；目标拉取并校验后记录新代次并启动业务。旧节点改为跟随，后续请求转向新写入节点。交接暂停时间取决于在途请求和最终同步大小。
4. 目标不可达或激活失败时，旧节点保持停止写入。持久状态会在重启后继续恢复，也可由原管理员会话重试当前交接；不要手工改回 writer、删除代次信息或启动旧普通服务。

监督进程使用独占目录锁、短期本机写入租约和业务进程锁；孤立旧业务进程必须退出后替代进程才能打开业务库。对失联写入节点**不自动晋升**：跟随节点能显示本地页面，但账号、管理 API、凭证刷新和发布会返回 503，过期资源租约也停止分发。突发整机损坏的离线强制恢复尚未实现；应在计划维护前完成交接。

本机「同步间隔」立即生效；单份配额用于后续快照，业务存储和 edge 缓存容量需重启本机对应进程才重新读取。默认单份 20 GiB；工作目录总预算为单份上限六倍，并检查剩余磁盘。保留近期完整副本、活动副本和最终交接副本，只清理专用目录内确认由本功能生成的旧副本和无引用对象。失败/中断残留可能占用预算，满额时暂停同步并报告错误，不删除活动数据；seed、edge 缓存和上传暂存还需单独留足空间。

站点管理 API 使用管理员会话：`GET /admin/api/sites`；`POST /admin/api/sites/settings`（`syncIntervalSecs`、`quotaBytes`）、`/sites/sync`、`/sites/transfer`（`targetId`）；普通模式另提供 `/sites/bootstrap` 生成初始配置。写操作要求 CSRF 请求头。内部 `/_site/*` 仅接受集群密钥，禁止代理缓存和公开记录敏感头。

### 个人设备凭证与管理器

共享 `THEME_STORE_TOKEN` 已不再参与资源认证，旧主令牌管理接口已移除。旧 APK 内置的共享令牌会收到 401，需要升级管理器。管理员显式签发的命名脚本令牌仍按原作用域生效。

- 管理器首次向 `/client/access` 申请每安装独立的只读凭证；登录时绑定该账号。访问凭证有效期 15 分钟，提前约 2 分钟通过 `/client/refresh` 轮换访问与刷新凭证。刷新期限默认 90 天，过期需要重新授权。
- 用户中心「API 与设备凭证」列出配置的站点 API，并可签发 1–365 天的个人设备凭证、一次性复制完整 JSON、查看和撤销设备。将 JSON 填入管理器自定义凭证栏即可导入；只复制 access token 将无法轮换。
- 新管理器默认凭证留空自动申请，刷新在实际请求时执行；同进程刷新串行，账号和站点分别隔离。生成及导入凭证均存于应用私有偏好并排除系统备份/设备迁移，目前未使用 Android Keystore 加密。过期或撤销后可在主题源设置「重置设备授权」，清空旧配置并保存，再测试连接重新申请。匿名申请默认开启，可在当前业务 `config.env` 设置 `CLIENT_GUEST_ACCESS=0` 要求登录。
- 数据库只存哈希；旧 refresh 重放会使对应凭证族失效，撤销与改密也会使设备授权失效。网络中断导致刷新响应丢失时需要重新授权，不能无限重放旧 refresh。只读设备凭证不能投稿或管理，投稿仍走账号会话及原有审核。
- 凭证响应 `no-store`；签发、刷新、个人列表及站点控制排除正文捕获，监控中的新设备令牌头会隐藏。已有审计/会话备份仍须按秘密保护。

### 本机回归

`cargo build --offline --locked` 后运行 `node scripts/test-sites.cjs`，在独立 loopback 进程中覆盖 A→B→A、旧代次拒绝、凭证轮换/撤销、重启与失联不晋升；运行 `node scripts/test-distribution.cjs` 验证资源复制和分布式上传，`node scripts/test-distributed-upload.cjs` 验证浏览器调度与页面脚本。它们不访问生产服务器，测试目录包含随机私密配置，不应提交。

## 以下为独立 edge 模式

以下章节描述**仅资源缓存**的 `edge`，其“不复制数据库、没有网站”的限制不适用于上面的完整 `site` 方式。完整站点内部会自动启动资源 edge 并生成当前写入端的分发配置；重启或交接时该内部配置会重新生成，持久成员变更应停机统一修改各站点 JSON。

在独立 edge 方案中，A 是主站和权威数据源，B 运行同一二进制的 `edge` 模式，保存已发布资源的磁盘缓存，也可接收私有上传分片。A 上的后台「分布式分发」（`#mirrors`）提供节点管理、自动选路、上传分流、同步状态和缓存设置。

## 拓扑与边界

```text
管理器 / 浏览器 ── HTTPS ── A 主站
                              ├── 登录、上传、审核、catalog.json
                              ├── account/authors/social/stats/audit 五个数据库
                              └── 已认证的资源请求：探测 → 302 到可用边缘节点
                                                       ↓
                                                    B 本地磁盘
                                                       ↑
                            专用节点密钥 + HTTPS 定期拉取清单与资源
```

- A、B 都必须有可达的 HTTPS 地址。家宽没有入站公网地址时，需要先解决可达性（例如可达的 IPv6 或现有隧道），本功能不绕过 CGNAT。只有 IPv6 的 B 无法服务 IPv4-only 的访客；主站探测也不能证明所有访客都能连接 B。
- 保留现有 Lucky TLS 链路。A 仍转发到 `127.0.0.1:8080`；B 的独立域名/端口转发到 `127.0.0.1:8081`。无须在 A 安装新的反向代理。
- 主站是数据库的唯一写入点；B 不运行第二套账号服务，不复制登录会话、主访问令牌或 SQLite 文件。
- 默认「自动」比较 **A 到各边缘节点** 的资源 HEAD 响应时间，以主站本地服务作为回退。此测量不等于访客到节点的延迟或下载吞吐量，也不保证跨运营商的最优线路；要实现每位访客的最优选择，需要管理器配合客户端测速。
- 不修改 DNS，也不做自动数据库故障切换。A 宕机后不能继续登录、上传或签发新下载凭证；B 的同步租约过期后停止分发。这是分发扩容，不是数据库高可用。

## 主站配置

1. 按现有流程构建并部署新二进制与 `static/`。构建入口仍为 `scripts/build-aarch64.ps1`，此变更包含 Rust 代码，单独热更新 HTML 不够。
2. 打开后台「分布式分发」，填写 A 的公网 HTTPS 根地址（保留实际端口，例如 `:8443`），保存设置。部署初期可以关闭分发，配置仍然可保存。
3. 添加 B 的名称、HTTPS 地址与优先级。创建成功后仅显示一次完整节点 JSON；将其保存在 B 的 `/etc/sukisu-theme-edge.json`，不要提交到 Git 或放入静态站点。
4. 在 B 启动边缘服务，开启 A 的「启用自建 CDN」，再点「立即同步」或等待轮询。点击「重新检测」可以立即检查节点进度。
5. 确认文件同步完成，再从 A 发起真实主题下载，检查重定向目标和文件 SHA-256。

主站节点配置存放在 `config.env` 同目录的 `distribution.json`，可由 `THEME_DISTRIBUTION_FILE` 覆盖；应用保存权限为 `0600`。设置通过 API 保存后立即生效；手工编辑该文件后需要重启主站。

每个节点有独立的 256-bit 随机密钥。普通 GET 状态接口不会返回密钥；创建和重置时仅返回一次。丢失配置可在后台重置密钥，再更新 B 的配置并重启 B。修改主站地址后也需要更新 B 本地 JSON 的 `originUrl` 并重启 B。

节点管理 API（沿用管理员登录与 CSRF 校验）：

- `GET/POST /admin/api/distribution`：状态 / 保存开关、主站地址、策略、轮询间隔和缓存上限。
- `POST /admin/api/distribution/nodes`：新建或修改节点；修改必须传已有 `id`，不会更换密钥。
- `DELETE /admin/api/distribution/nodes/{id}`：移除节点。
- `POST /admin/api/distribution/nodes/{id}/rotate`：重置节点密钥。
- `POST /admin/api/distribution/nodes/{id}/sync`：请求边缘节点重新拉取清单，异步执行，返回成功只表示请求已接收。
- `POST /admin/api/distribution/probe`：并行探测节点状态。

这些控制接口不进入正文捕获式 API 监控，以免将一次性密钥写入监控数据库；管理操作仍写入不包含密钥的审计日志。

## 边缘节点运行

B 使用与自身系统/架构匹配的二进制。仓库现有脚本构建的是 Linux aarch64-musl；若 B 是 x86_64，不能直接运行该产物，应使用该架构的原生构建或相应工具链。

直接运行（先准备后台生成的 JSON）：

```bash
/opt/sukisu-theme-web/sukisu-theme-web-rs edge /etc/sukisu-theme-edge.json
```

生成配置的默认值：

- `bind`：`127.0.0.1:8081`，供 Lucky 等 HTTPS 入口反向代理。
- `cacheDir`：`/var/cache/sukisu-theme-edge`，必须是本节点独占的绝对路径。
- `quotaBytes`：`10737418240`（10 GiB）；至少 128 MiB，且必须能容纳全部已发布资源。容量不足时拒绝新清单并报告错误，不会假装同步完成。
- `nodeId` / `secret`：后台签发的节点身份；`originUrl` 指向 A。

仓库提供 `scripts/sukisu-theme-edge.service` 供 Linux/systemd 使用。安装服务前创建专用 `sukisu-edge` 用户，将私密配置的所有者设为该用户、权限 `0600`；服务通过 `CacheDirectory` 创建其缓存目录。模板默认仅允许写入 `/var/cache/sukisu-theme-edge`，修改 JSON 的目录时也要同步调整服务的 `ReadWritePaths`。本次代码修改不会自动安装系统服务、修改 Lucky、开放端口或部署到服务器。

公开资源路由仅接受主站签发的短期下载凭证：

- `/themes/*`、`/previews/*`、`/screenshots/*`、`/avatars/*`。
- `/_edge/status` 和 `POST /_edge/sync` 必须携带 `X-Sukisu-Node-Key`。
- `/healthz` 仅返回进程角色和存活信息，不能用于判断资源是否已同步。
- B 没有账号 API、独立发布、管理后台或数据库下载路由；仅提供有凭证的分片暂存接口。

管理器的资源路径、网页用户中心的已发布主题下载/预览、管理员的已发布图片预览共用同一分发逻辑，仍先执行各入口已有的令牌、登录和归属校验。作者自己的撤回主题、私人头像和待审预览继续留在主站。新 edge 模式不需要客户端转发主访问令牌，下载只依赖主站签发的短期凭证；旧 `mirrors.json` 的令牌契约不变。

节点到主站的清单和资源 API 使用 `X-Sukisu-Node` 与 `X-Sukisu-Node-Key`，只允许读取当前已发布的资源。该凭证不能调用管理员 API，也不能读取 `pending/`、数据库或配置文件。不要将这两个头配置到外部访问日志中。

## 分布式并发上传与合并

后台「分片上传同时使用主站与边缘」和节点「允许此节点接收上传分片」默认勾选，仍需启用自建 CDN 总开关才会分流。可以单独关闭流量不足的节点上传入口，保留下载能力。A、B 都要升级二进制，A 同时更新 `static/distributed-upload.js`、`index.html` 和 `account.html`。

1. 登录后向 A 创建拥有者绑定的文件上传会话。A 返回本地入口及边缘入口的 30 分钟凭证，绑定会话 ID、总大小与分片大小；不会把登录 Cookie 或节点长期密钥交给边缘客户端。
2. 网页使用 4 路并发队列，直接向 A / B 发送不同分片。根据已测吞吐量与在途请求领取后续分片，较快入口可以接收更多；不是固定各传一半。空闲 30 秒、网络失败或相对已测可用入口明显过慢时切换重试。
3. B 检查凭证、来源、租约、长度、磁盘和配额，将分片落盘，再向 A 确认回执。A 确认后网页才计为接收成功；重复内容相同可重试，内容不同拒绝覆盖。
4. 最后调用 A 的 `POST /uploads/{id}/complete`，A 最多 4 路并发取回 B 的分片并核对长度与 SHA-256。B 掉线时返回缺失序号，网页只补传这些分片到 A，不会把回执当成完整文件。
5. 主题包、预览图、作者头像和截图全部支持该流程。最后向原有上传接口提交元数据与会话引用，A 保留原有权限、作者归属、包格式、图片处理和审核检查，统一写数据库。B 不参与数据库双写或独立发布。
6. 发布后的完整包与处理过的图片继续由清单同步到 B。待审文件只在私有暂存区，不会进入已发布资源清单。

边缘 `uploadQuotaBytes` 是独立暂存上限，默认 1 GiB、至少 128 MiB，与已发布资源的 `quotaBytes` 分开。目录为 `cacheDir/upload-staging`，不要配置成静态网站。完成/取消会话后 A 尝试清理对应暂存；无法连接时由节点使用量检查清理超过 24 小时的会话目录。中断后使用相同文件指纹重新初始化可刷新过期凭证并继续。

上传 CORS 只允许配置 `originUrl` 的浏览器 Origin，并支持 OPTIONS 预检。跨站上传不发送主站 Cookie；通过额外别名域名访问后台时会回退主站。客户端只使用短期凭证，禁止内置节点长期密钥。

会话 API 沿用 `/api`、`/admin/api`、`/account/api` 下的账号认证与 CSRF：

- `POST /uploads/init` 新增 `uploadTargets`，包含节点 `baseUrl`、`id`、`ticket`。
- 向 `baseUrl/{index}` POST 原始分片，边缘头为 `X-Sukisu-Upload-Ticket`；本地入口保留已有登录与 CSRF。
- `POST /uploads/{id}/complete` 返回 `complete` 和 `missing`，完成后提交原有 `uploadId`。
- 图片引用为 `previewUploadId`、`avatarUploadId`、可重复的 `screenshotUploadId`。旧 multipart 文件字段仍兼容。
- `POST /distribution/upload/receipt` 仅允许已授权且分配给该会话的节点确认回执；`GET/DELETE /_edge/uploads/...` 仅供 A 使用节点密钥取回和清理分片。
- 含上传凭证的会话接口不进入 API 正文捕获，且一律 `no-store`。

Android 管理器源码位于配套的 `SukiSU-Ultra/manager` 仓库。新的上传实现消费 `uploadTargets`：主题包、预览图、头像和截图串行创建会话，每个文件最多 4 路并发分片；按在途数量与实际吞吐量调度，并在同次投稿的文件之间复用测速结果。边缘失败、空闲超过 30 秒或相对可用线路明显过慢时换路；边缘 401/403 仅使该线路失败，主站 401 才表示账号登录失效。

管理器向边缘发送请求时使用独立的 HTTP 客户端，只带短期 `X-Sukisu-Upload-Ticket`，不继承主站 Cookie、账号/主题令牌、拦截器或认证器，也不跟随上传重定向。即使会话显示所有分片已接收，仍调用主站 `/complete`；缺片仅补传到主站，完成后才提交图片会话引用。取消上传会取消在途请求。旧服务器没有 `uploadTargets` 字段时继续使用原包分片和图片 multipart，不调用其不支持的 `/complete`；新服务器返回空数组时仍执行合并确认。需要重新构建并安装管理器才会生效，升级服务器不能让旧 APK 自动分流。

**性能边界：**可以分担客户端到 A 的单一入口限速或跨运营商瓶颈，但客户端总上行、两机互传、A 总入站限额和最终存储仍会限制总速度。当前在 A 合并，边缘分片必须回传到 A，会增加流量，不能绕过 A 的整机总流量额度。发布后两边保存完整文件也需要同步流量。A 宕机时无法确认回执或完成发布，这不是离线双主。

本机回归验证：`cargo test --offline --locked`、`node scripts/test-distributed-upload.cjs`。先运行 `cargo build --offline --locked`，再运行 `node scripts/test-distribution.cjs`，会在 `target/distribution-e2e-*` 创建独立数据库和随机测试凭证并启动两个 loopback 进程；结束后停止进程，不访问生产服务器。测试目录包含私密测试配置，不要提交或公开。

## 同步、缓存与故障处理

1. 默认每 5 秒拉取一次清单（后台可配置 2–60 秒）。主题包、预览、截图和作者头像全部纳入；账号私人头像、草稿和待审文件不复制。
2. B 使用两路并发流式传输，逐文件核对长度和 SHA-256，校验成功后原子发布为 `objects/<sha256>`；未验证文件不能对外提供。
3. 独立心跳与资源传输同时运行，大文件传输不会阻止续租。同步延迟是 **轮询间隔 + 传输/校验时间**，没有跨服务器的即时事务保证。
4. 新清单撤回/移除某路径后，B 立即停止为该路径提供新响应；后台再清理不属于当前清单的缓存对象。不会扫描或清理独占缓存目录以外的文件。
5. 启动后先从 A 获取有效清单，并重新校验已有磁盘对象；不把旧缓存直接当作可信内容。
6. 清单租约为 `max(15 秒, 轮询间隔 × 3)`；断网超过此时间后 B 返回 503。明确的 401/403/503 响应会立即使旧租约失效。主站关闭分发、禁用节点或轮换密钥后，节点在下一次清单请求时失去授权。
7. A 并行探测请求的实际文件，并检查 B 返回的摘要；探测超时上限 2 秒。成功选择缓存 5 秒，失败缓存 2 秒；缓存过期后重新探测。B 不可达、未同步或摘要不同，A 在发出 302 **之前**回退到本地/原有镜像。302 后链路突然断开仍需客户端回到 A 重试，不存在透明的跨服务器续传。
8. 带 `Range` 的主站请求继续留在 A；已经拿到有效 B 地址的客户端可在同一凭证、同一摘要上向 B 发起 Range 请求。凭证过期后需重新向 A 请求。
9. 下载凭证使用现有 AES-256-GCM，绑定资源路径、摘要和 120 秒有效期，不包含主访问令牌。下载地址属于短期能力链接，不要传播；配置反向代理时避免记录 URL 查询串中的 `ticket`。
10. 磁盘是自建 CDN 的主要缓存；浏览器使用 `private, max-age=..., must-revalidate`，其有效期不超过后台配置、下载凭证和剩余租约中的最小值。私有内容不设置 `public`，不要在 Lucky 或其他代理中强制忽略此策略缓存受保护资源。登录、API 和目录继续回到 A，不缓存会话或动态数据。

主站每 15 秒探测一次节点状态，后台可手动刷新；页面每 10 秒更新已有状态。节点健康面板的延迟是控制面响应时间；默认选路另行探测实际资源，不能把健康面板延迟当作客户端测速结果。

## 数据库与备份

当前账号与业务 SQL 使用 SQLite 特有语法及四个 `ATTACH` 数据库；本功能保持这个存储契约，**没有实现数据库实时复制或多主写入**。WAL 数据库不应通过网络共享目录让两台服务器同时打开，也不能通过持续覆盖运行中的 `.db` 文件来实现主从。

两台机器的推荐分工是：业务数据仍在 A 的 `THEME_DB_DIR`，B 保存文件副本；数据库另外做异机灾备。需要一致恢复点时，在维护窗口停止全部写入进程，完整备份该目录（包括五个库及存在的 WAL/SHM）、`meta/`、`catalog.json` 和受保护的配置，再把已完成的快照复制到另一台机器或独立存储。备份包含个人信息、令牌和审计记录，必须限制访问。不要把这些备份放入 edge 的公开资源树。

若要求 A 故障时 B 继续登录/投稿，则还需要独立的数据库与控制面容灾设计：SQLite 单主日志复制并带故障隔离，或者迁移为带主从复制的客户端/服务器数据库；都需要覆盖全部 SQL、会话、统计、作者、审计和事务边界，不能只在页面上打开一个开关。两节点自动晋升还需仲裁/隔离设计以防网络分区双写。

## 验证与回退

在测试环境使用 loopback HTTP 地址可做本机联调，生产地址只允许 HTTPS。使用现有管理器从 A 下载一份主题，确认：

- 分发关闭：保持原服务路径。
- B 未同步、离线或摘要不符：A 不向 B 重定向。
- B 文件校验完成：A 返回指向 B 的带短期 `ticket` 的 302，B 文件 SHA-256 与目录一致。
- 请求 B 没有凭证、篡改路径/摘要、凭证过期：403；有效凭证的已撤回资源：404；租约过期：503。
- 暂停 B 后，等待 5 秒选路缓存过期，重新从 A 下载应由 A 回退处理。
- 开启维护模式：主站资源受维护限制，B 在下一次清单刷新后暂停分发；已存在的浏览器缓存最多保留剩余租约时间。
- Range 在 A 不发生重定向；HEAD 不增加主题下载统计。

回退时在后台关闭「启用自建 CDN」，A 立即停止签发新的边缘地址并保持原有分发路径。B 在下一次清单轮询后失去授权；不需要删除缓存或改动数据库。旧 `mirrors.json` 独立保留，若也不想使用旧镜像，需另外禁用其配置。

参考：[SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite 网络访问限制](https://www.sqlite.org/useovernet.html)、[HTTP 缓存控制](https://www.rfc-editor.org/rfc/rfc9111.html)。
